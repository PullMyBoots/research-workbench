# Research Topic Control Space

`.DiscoveryProgram/` is the control surface shared by the Human and Main Agent for one research Topic. This template intentionally starts without a Topic-specific objective, external source, Team Problem, baseline, version, evaluation result, or history.

## Layout

```text
.DiscoveryProgram/
  problem_registry.json            canonical Team Problem index; empty at initialization
  knowledge/
    items/<item-id>/               complete Topic-level external source bundles
    items.json                     item ids, names, paths, and summaries
    topics.json                    Main-written syntheses over Items
  memory/
    main.md                        required cross-session Main briefing
    logs/<id>.json                 immutable @memory progress records
  integration/                     cross-Problem interfaces and acceptance evidence
  log/                             Topic-level administrative logs
```

Topic knowledge serves the whole research Topic. Each registered Team Problem owns a separate local knowledge base, Baselines, formal Versions, metrics, jobs and evaluator state under `subprojects-team/<problem-id>/`. Do not combine scores, rankings or practice across Problems merely because they belong to one Topic.

## Initialization

Before substantive research, Human and Main should write the Topic objective and necessary background into `memory/main.md`. Its other two sections hold evidence-grounded metacognition and the current progress with necessary file indexes. This is a judgment-bearing artifact: it is not automatically generated by the runtime.

Use `problem_registry.json` only for Team Problems created after Human/Main decide that a shared Candidate/Evaluation interface makes parallel search worthwhile. Main direct work in `subprojects-main/` and independent single-Agent projects in `subprojects-single/` do not need registry entries.
